# Component Guidelines

Use this when working on frontend components.

## Component Structure

- Keep components focused on one responsibility.
- Prefer existing UI primitives and local component patterns.
- Keep data fetching, mutations, and presentation responsibilities clearly separated.
- Use accessible labels, semantic HTML, and keyboard-friendly controls.
- Keep Dayframe timer surfaces category/task-first. Avoid exposing projects/clients in primary timer UI.
- On web, Dashboard and Timeline must consume the one timer runtime mounted by `AppShell`. Route components must not mount an independent active-timer poll, store, API client, mutation queue, shortcut handler or manual-entry owner; navigation between those routes must preserve the same optimistic state and active-entry identity.
- Keep the persistent web timer on one explicit measured track: a flexible `minmax(0, 1fr)` task compound control, bounded Category and time tracks, a stable Play/Stop slot, and one final icon-action slot where idle Plus becomes running More. Idle/running swaps must preserve outer geometry; compact layouts may reflow the task field to its own row but must not shrink or overlap the remaining actions.
- Manual-entry Suggestions must reuse timer suggestion ranking and metadata without invoking timer start. Selecting one fills the manual draft's Description, Category, and Tags. Cap the visible result set to a documented number of complete content-safe rows; never force a two-line title/metadata row into the generic 44 px touch minimum or crop a partial final row. Its Tags/Suggestions surfaces remain out of flow, anchor to their actual triggers, and must not require scrolling the dialog merely to reveal the options.
- Add time must reuse the timer Category option treatment rather than a separate native select. Date/time controls retain click-to-select behaviour and use a Dayframe-owned calendar/time surface when the opened browser-native picker cannot be themed; styling only the closed native field is not sufficient evidence. Dialog child surfaces must preserve the dialog's rounded silhouette without forcing floating pickers back into a clipping container.
- Timer-owned Suggestions, Tags, Categories, and start-time surfaces must use the shared floating-surface treatment and escape the timer panel's clipping boundary. Keep their lists internally scrollable, their triggers visually connected, and phone-width variants fully inside the viewport; do not substitute a scrimmed modal for an anchored timer editor.
- `CategoryPicker` owns contextual category creation for the idle/running web timer, Add Time, Timeline List entry editing, and Calendar create/edit. Every create-enabled instance portals its panel outside the editor's scrolling content: use the nearest native `dialog` root when one exists and `document.body` otherwise. Match the category field width, prefer a 6px below-trigger gap, flip above when required, clamp to 12px viewport gutters, recalculate for panel/trigger resize plus page/visual-viewport scroll, resize and zoom, and keep only the panel internally scrollable with a 220px maximum. Opening the list or Create state must not change the surrounding editor's bounds, `scrollHeight`, or `scrollTop`; all portalled category surfaces remain inside the editor's outside-pointer, blur, Tab, focus-trap and Escape interaction boundary. Closed fields and list options show the category's circular, borderless, shadowless colour dot. The final option swaps the list for a bounded inline editor without mounting a nested form: place the accessible colour-dot action inside the leading edge of the Category name compound control instead of adding a separate Colour row, preview the same deterministic automatic colour the server will assign, allow an optional choice from all 30 canonical palette colours in the shared five-column order, and keep the colour palette in its own viewport-clamped floating surface so neither editor nor category panel reflows. Create is a standalone workspace catalogue mutation: send the trimmed name plus only an explicitly chosen palette key, keep `isPinned=false`, publish the returned row to shared bootstrap state, then select it in the local draft. Never submit, dismiss, start, stop, restart, save, or reset the surrounding entry; Description, Tags, dates and times remain under their existing owner, while the category survives later draft discard. Block blank and case-insensitive duplicate active names on both client/server boundaries; failure retains name, chosen colour, draft and focus for retry. Enter belongs to category Create; Escape closes Colour, then returns to the option list, then the trigger; arrow/Home/End navigation includes Create and colour-grid navigation; phone widths keep a 12px viewport gutter plus 44px targets. Reports, Review, Places and Automations must not opt into contextual creation.
- `CategoryPicker` also owns its create-state visual anatomy across hosts. Use 14px/650 for the embedded heading and actions, 12px/650 for the Name label, and 14px/400–500 for input and option text. Centre the 20px create swatch in a 44px leading action inside the field's 2px perimeter, producing a 14px visible edge inset and 24px centre offset. Its final list action uses a separate 1px divider inset 12px with 6px clearance before the rounded action surface; it must not use the action's border or inset shadow. Timer and compact-editor rules may style only their direct option rows, never every descendant button or the shared create form.
- The running start-date/time editor is content inside the persistent timer form, never a nested form. Enter and pointer Save must call the same direct update path, prevent outer timer submission, update elapsed state immediately, and persist after bootstrap reconciliation. Calendar/clock affordances may remain pointer-clickable but must use `tabIndex=-1` when the segmented native date/time control already provides the editable keyboard stops.
- Web date selection uses `DayframeCalendar`: a stable six-week grid with muted, selectable adjacent-month dates. Date-time consumers add their own typed time control; date-only consumers must not fork the calendar geometry.
- Reports filter disclosure content is a floating surface, not in-flow expansion. Categories, Tags, Place, Source, and More filters must preserve the report layout below them, use bounded internal scrolling, and keep URL-backed multi-selection semantics.
- Web workspace management uses one compact selector with immediate switching; Rename and New workspace reveal only their relevant form. Profile-menu workspace rows use the same flat, fill-led menu treatment as Settings and Log out, without per-row elevation.
- Category identity uses circular colour markers. Colour-choice controls must keep an accessible target while the visible swatch remains circular, borderless, and shadowless; selected state comes from focus/selection treatment rather than changing the swatch shape. Category Save is text-only and Edit uses a pencil.
- The desktop sidebar may expose one icon-only Light/Dark toggle immediately above Help & Shortcuts. Its accessible name describes the destination theme, and it switches from the resolved System appearance to an explicit opposite choice.
- Route-level Settings should consume the shell's last successful bootstrap snapshot and refresh quietly. A full loading state is only for a tab with no cached authenticated data; background reconciliation must not blank the route, cross user/workspace boundaries, or overwrite an active form.
- Custom checkbox switches must explicitly own track and thumb geometry (`appearance`, fixed/min/max dimensions, border radius, padding, and box sizing) so iPad/WebKit touch styles cannot distort the pill.
- For positioned web Calendar blocks, use one structured primary line in `Description · Category · #FirstTag +N` order at every readable height, including `title` overlap lanes. Description is semibold primary text; Category is muted normal weight; the first tag is muted bold; `+N` is muted medium. Actual rendered widths at or below 111px hide the metadata spans and retain Description only; below 18px or at `none` density show no text. The independent full-entry `Duration (Start – Finish)` secondary line starts only at the safe 48px height. Running state must not reduce whole-block text opacity.
- Live web Calendar blocks use one compact radius across densities and a subtle category-derived hairline border over the soft category fill; do not restore a leading accent rail. Selection is fill-led, while keyboard focus alone owns the explicit focus perimeter.
- Separate touching Calendar blocks with visual-only vertical and horizontal gaps after semantic time/lane calculation. Do not falsify timestamps, durations, snapping, overlap classification or minimum-height collision inputs to create spacing.
- Calendar overlap layout uses shared deterministic intent: isolated entries are full width; a substantially shorter interval contained within one longer interval may use an inset overlay that leaves the longer rail visible; partial, similar, or multi-entry collisions use equal lanes; dense lanes may suppress text. Renderers own only geometry interpolation and hit testing. Every visible block must remain the tap target for its semantic entry.
- A positioned Calendar container must not itself be an interactive wrapper around actions. Give selection/details one primary action, keep restart and pointer-resize as siblings, provide keyboard and touch equivalents for hover actions, and define a minimum rendered height before mounting direct resize handles.
- Inline Calendar Play is pointer-hover-only and must have an equivalent keyboard/touch Start again route in the selected action surface or editor. Completed blocks at least 24px high may mount Play regardless of lane text density; selected, running, resizing, sub-24px, coarse/hoverless, and rendered widths below 28px hide it. Keep Play above the resize strip only within its own right-edge action zone so the remaining resize handle stays usable; never let the two hit targets intercept each other.
- Calendar and List restart actions must reuse the shell-owned timer runtime and its mutation gate. Copy only category, description, and tags unless the timer contract is deliberately expanded in a separate change.
- Web Calendar, Timeline List, and Reports entry editing share one `TimeEntryQuickEditor` controller/panel contract. Calendar renders it in one `document.body` portal anchored to the exact selected rendered fragment by a stable entry/block identity; List and Reports render the same panel in a centred, focus-trapped, mobile-safe modal. All edit entry points, including Calendar pointer, Space, Enter, and double click, must reach this shared editor; do not restore `EditTimeEntryDialog`, an advanced Calendar editor, or an in-flow bottom action card.
- The shared quick editor owns Description with reusable Tags, Category, explicit Start date/time, completed-entry Finish date/time, and completed/new minute-only `HH:MM` Duration. Exact canonical seconds remain internal and survive no-op and non-temporal saves; a deliberate Duration edit resolves to whole minutes. Running Duration is live, minute-only, and read-only and running Finish reads `Running`; a ticking duration is presentation state, never a dirty draft value. Start/Finish date triggers reuse the portalled `DatePickerPopover`/`DayframeCalendar`, show only a bare calendar icon inside the same seamless compound field while closed, and return focus to that icon when dismissed. The compact temporal row shows a subtle `+N` beside Finish when its local date is later than Start. Plain Enter in focused Description uses the shared Save path only after hashtag suggestion, modifier, and IME precedence. It does not expose Place or task Suggestions.
- Shared quick-editor saves emit only owned partial keys (`description`, `categoryId`, `tagNames`, `startedAt`, `stoppedAt`). Tags hydrate from the entry, use the shared maximum and create/select/remove behavior, and stay in the same draft/discard boundary as the other fields. Save, Start again and Delete establish one synchronous mutation owner before awaiting: the complete editable form—including Description, selected tags and tag panels—is disabled, duplicate/conflicting actions are gated, the dialog exposes busy/status semantics, and failure restores the exact draft plus the initiating focus. Start, Finish and Duration validation inputs describe the mounted editor-scoped error element only while their corresponding error is visible. Hidden Place and compatibility metadata must survive every save and active-timer optimistic update. Calendar and Timeline List may expose Start again and Delete; Reports exposes neither, and List grouping continues to edit its existing representative occurrence.
- Calendar empty-space creation is owned by one primary fine mouse-pointer down/up sequence on the day body. Require the same pointer and day, movement below the drag threshold, unchanged Calendar scroll, an eligible underlying target and no active resize or consumed-dismissal token. Reject touch/coarse input, right-click, drag, scroll, cancellation, headers, axes, scrollbars, blocks/actions/handles, the temporary anchor and each block's full semantic time rectangle, including any visual-only gap.
- Click-to-create floors local wall time to the preceding 15-minute slot and proposes an exact 30-minute interval. Use a discriminated create target rather than a fake `TimeEntryRow`; render one `aria-hidden`, `pointer-events: none` provisional anchor whose geometry follows draft Start/Finish and zoom without entering canonical entries, totals or lane layout. At 23:45, Finish is 00:15 on the next local date.
- Create mode reuses the compact editor's Description/Tags compound control, Category, Start, Finish, Duration, Close, Save, validation, overlap, fixed feedback plane and responsive placement. It starts blank, tagless and Uncategorized, uses minute-only `HH:MM` Duration, omits Play/Delete, treats the click baseline as clean but valid to Save, and sends only selected `tagNames`, optional trimmed Description/Category and exact timestamps through the existing manual-entry runtime. Retain the exact draft/anchor on failure; dismiss only after canonical refresh; never mutate the active timer.
- All web focus indicators use the reusable neutral grey `focus`/`control-border` treatment. Text/date/time/select/textarea fields show their neutral focused border for pointer and keyboard focus; buttons, links, tabs, dropdown/icon actions and other non-field controls show a neutral indicator only under `:focus-visible`. Never use browser-blue, `info`, or accent colour to communicate focus. Selected/active states remain independent, and an invalid focused field retains its danger cue alongside neutral focus.
- Compact Calendar controls use that neutral focus treatment. A clean outside click dismisses; Close, Escape or an outside click after any exact draft-value change must switch the fixed feedback plane to exactly `Discard changes?`, `Go back`, and `Discard`, blocking the underlying action. The plane priority is `discard > validation/save error > overlap > empty`; compact overlap content is only a warning triangle plus `Overlaps with N entry/entries by HH:MM`. State changes must not resize or move the editor, and long errors scroll inside the fixed plane. Go back or Escape returns exact focus/draft; Discard uses the editor exit owner. The outside-pointer owner must publish exact pointer identity before dismissal so that pointer cannot also create an empty-space draft.
- Compact Calendar temporal saves have one active owner and synchronize as soon as the active input is complete and valid: Start preserves the exact current duration and moves Finish; Finish recalculates exact Duration; Duration keeps Start and moves Finish. Incomplete time input remains raw with no immediate error until blur/Save. Duration accepts minute counts (`30`, `30m`, `90`, `90m`), `H:MM`/`HH:MM`, written hours/minutes, and compatibility `H:MM:00`; it normalizes to unbounded-hour `HH:MM`, rejects explicit non-zero seconds, and has a one-minute edited minimum. Untouched exact timestamps and hidden seconds remain byte-for-byte canonical, including sub-minute entries displayed as `00:00`. Manual Finish less than or equal to Start remains visible and reports exactly `Finish must be after Start`; only the initial click-created midnight interval may roll to the next day. Ambiguous wall times choose a valid positive interval closest to the exact sources, and nonexistent wall times are invalid. Saves emit only owned partial fields; future Start/Finish remain invalid in the client and authoritative API.
- A running compact edit must use the shell-owned timer mutation gate and atomically project the same Description/Category/Start values into bootstrap collections and the persistent timer draft. Preserve hidden tags, place and compatibility metadata; issue one PATCH plus one forced refresh; apply authoritative `updatedAt`; cancel/gate stale debounced timer writes; and roll both snapshots back exactly on failure.
- Calendar portal placement is fixed and measurement-driven: prefer 8px below, flip above, clamp at 12px, and use a full 12px-gutter bounded phone card. Observe the anchor, panel, Calendar scroller, viewport and visual viewport; recompute on scroll, resize and zoom; never animate `top`/`left`; close if the anchor is detached or no longer intersects the Calendar viewport.
- Keep the iOS dashboard focused on logo/header, active timer, start task, quick category actions, and Today summary.
- Move location and HealthKit permission controls to onboarding and Settings.

## State And Forms

- Prefer controlled form state only where it adds clarity.
- On web, use the shared field/control classes before adding route-local geometry. Inputs with nested reveal, clear, tag or search actions must use one compound wrapper focus owner; do not stack wrapper and input perimeters.
- In editable web Description controls, a selected tag is a normal-weight plain-text remove action with no default fill and a thin visible `X`. Keep its button target 44px high while a separate 22–24px visual wrapper owns the hover/focus fill, darker accent text and compact `6px` radius; the hidden width measure must mirror that label-plus-X wrapper. Clicking the text or `X` removes the tag. Keep this shared between the persistent timer and `TimeEntryQuickEditor` instead of styling each surface separately; `+N` overflow stays quieter and neutral.
- Validate at the boundary before persistence.
- Show loading, empty, success, and error states for user-facing actions where they help the user understand the state. Inline Calendar restart failures use the established fixed feedback surface and an assertive alert without moving Calendar layout.
- For normal mobile timer mutations, loading UI should be invisible: start, stop, edit, delete, and suggestion-apply actions should update optimistically, then reconcile silently. Do not add spinners, progress bars, or layout-moving loading rows for these paths. Keep visible spinners for deliberate pull-to-refresh only.
- Mobile Review items use separate fill-led cards with the detected activity and minute-level time range as the primary hierarchy. Show confidence as five real circular indicators plus an accessible text label, keep overlap as one compact inline warning, and keep source strings, Health reprocess diagnostics, raw sample counts, retention windows, and uncertainty internals out of the normal card. The Location Evidence route leads with activity, concise time range, and map; advanced resolution actions remain available below without creating a second data or mutation owner.
- Task title is optional. Category is optional and should be editable while a timer is running.
- Running-timer suggestions are metadata completion for the existing active timer. Empty Play starts one bare timer then opens the running edit sheet; Play while a timer is already running should open the same suggestion/edit flow. Applying a suggestion must update that active timer, not create a second timer.
- On mobile, presentation-retained active-entry snapshots may feed the editor's coordinated exit only. Once an entry belongs to a pending deletion, the Today card must resolve directly to idle and must never render that retained snapshot as a blank active timer. Hashtag entry must keep synchronous text/caret authority and generation-scoped, monotonic focus intent so late native selection or blur events cannot hide the chooser or dismiss the keyboard. Native typing owns its caret; programmatic hashtag edits may control selection only for the bounded acknowledgement they require. Never treat transient `Keyboard.metrics()` absence as permission to blur an already focused Description, and cancel pending focus intent as soon as its hashtag becomes inactive. A time-entry sheet with a bottom destructive action must keep that action reachable across device heights, Dynamic Type and keyboard occlusion even when the first content measurement says the form fits.
- A fixed single-screen mobile time-entry form must use deterministic height/Dynamic Type density rather than re-enabling vertical sheet scrolling. Keyboard occlusion may temporarily cover lower controls when the product contract explicitly permits tap-outside dismissal. Keep horizontal Category and bounded Tags/Suggestions result scrolling scoped to those controls. New tag creation is an independent idempotent catalogue mutation at the Create action, not a side effect deferred to time-entry Save.
- Keep the native stacking context of every focused mobile `TextInput` stable: never conditionally toggle `zIndex`, reparent, or reorder one of its ancestors during an overlay transition. Keyboard-continuity QA must require zero blur-recovery events across the transition, not merely a focused field and visible keyboard afterward.
- The `Done` action for every `ActiveTimerEditSheet` mode belongs in one outer-sheet top-action layer: its top and right offsets use the same named inset, never mode-specific header coordinates.
- Surface friendly, actionable permission messages; never display raw native exception strings to users.
- Treat route state as the source of truth for same-route mobile sub-settings. Do not mirror the active route section into local state or intercept native back gestures to repair duplicated navigation state.
- For inline iOS forms near the bottom of a scroll view, keep the focused input mounted, apply the native keyboard inset, and reveal the complete required control group—not only the text field—above the keyboard at normal and Dynamic Type sizes.
- When timer state is mirrored to a native system surface, serialize reconciliation and make the latest requested state win; optimistic and persisted entry updates must not race separate native lifecycle calls.

## Motion Ownership And State

- Read `.codex/reference/motion.md` whenever a component introduces visible movement or changes layout over time.
- A moving component must expose or own a complete state sequence: entrance, update/reflow, exit, cancellation, and async rollback where applicable. Do not leave a parent to animate one half while a child mounts or disappears abruptly.
- Prefer an existing motion primitive and `MOBILE_MOTION` token over local duration constants. Local list, notice, picker, confirmation, and expansion motion should stay on the UI thread when possible.
- Keep stable keys and deterministic replacement rules so rapid actions do not replay stale exits, dismiss newer feedback, or restore obsolete state.
- Do not add a Swift component to repair ordinary React Native presence or layout motion. Choose native ownership only for a documented platform interaction need.

## Native iOS View Boundaries

- Use a standard local Expo module for a targeted Swift/SwiftUI view that lives inside the existing Expo app. Export an `ExpoView`, retain one `UIHostingController` for its SwiftUI hierarchy, and update its observable model through typed Expo `Record` props/view events. Do not use the experimental inline-module path, create a second app target, or migrate unrelated screens in the same PR.
- React Native remains responsible for authenticated bootstrap data, API mutations, active-timer truth, selected route state, and presentation of the existing timer/entry/Review sheets.
- Pass the native Calendar a serializable presentation model: selected/today day keys, week days, total, entries with timestamps and state flags, category display metadata, resolved theme roles, and accessibility/reduced-motion preferences.
- Emit semantic actions such as select day, change day/week, open active timer, open completed entry, and open review item. Swift must not fetch Dayframe APIs, write the offline queue, or own a second copy of the timer/domain model.
- Preserve native view identity across ordinary React prop updates so ticking time, bootstrap refreshes, and optimistic reconciliation do not reset zoom or scroll unexpectedly.
- Give the timeline one gesture and vertical-scroll owner. A SwiftUI Calendar may wrap `UIScrollView` with `UIViewRepresentable` for continuous focal-point-preserving zoom; do not nest a competing React Native pinch/pan handler around it.
- Map stable entry/review identifiers through callbacks and add contract tests for serialization, callback routing, and no duplicate mutation path.
- Native Calendar blocks use one nominal compact radius across densities; very small paths may clamp only to fit their actual rectangle. Do not introduce short/tiny capsule tokens.
- Keep semantic, visual, and hit geometry separate. A visual Calendar gap may shorten only the painted fill, hatch, stroke, text, metadata, and marker; it must not change timestamps, semantic block position/height, overlap lanes, density thresholds, totals, or callback hit math.
- When an isolated short Calendar entry expands to the minimum touch height, keep the expanded target centred on the semantic slot and offset the painted content within that target so its visible top remains the exact semantic top. Never let the minimum hit frame become the block's visual origin; overlapping entries continue to use semantic-height targets.
- Derive confirmed/active native block borders from the category cue and semantic Calendar border. Preserve the neutral Review dash, active dash, Uncategorized hatch/boundary, and continuation exception without adding a new colour bridge field.
- Native Calendar blocks do not gain desktop hover actions such as Play. Swift emits only the existing semantic open actions; React continues to own editing, Review, timer mutations, and persistence.
- Native Calendar empty-time creation uses the full lifecycle of one retained UIKit long press in the existing `DayframeCalendarScrollCoordinator`; do not add a SwiftUI long-press modifier, React Native Gesture Handler owner, second scroll view, or delayed timer. `.began` publishes one native-only fixed 30-minute provisional block without emitting to React; `.changed` moves the whole block through 15-minute floored slots using the captured finger-to-block grab offset; `.ended` clears provisional state before emitting exactly one unchanged `dayKey`/`startMinute` request. Cancel, failure, stale day/layout, refresh, app inactivity, detachment and hosting removal clear without a request or sheet.
- Reject initial native Calendar creation with the same semantic Button hit frames used by rendering, including isolated 44-point short-entry targets, overlap-lane semantic height, continuation blocks, and the one-point visual-only gap. Do not mark a whole time row occupied when the touched horizontal lane is empty. After valid empty activation, the provisional block may move over canonical entries so the existing Add sheet can own the overlap warning.
- The provisional block belongs to the observable Swift model and root renderer, never `modelJSON`, `presentation.entries`, totals, overlap allocation, networking, persistence, or the active timer. Render it above canonical entries with the shared 8pt radius, one-point boundary/gap and continuation corners plus a restrained accent-derived temporary treatment. It is hit-test/accessibility hidden and has no category, tags, Play, warning marker, or resize handles. Normal same-day presentation updates preserve it; token-scoped cleanup prevents stale sessions from clearing a newer preview.
- Before `.began`, normal vertical scroll, horizontal swipe, pinch, refresh, second touch, hour-axis and semantic entry-hit rejection remain authoritative. After `.began`, creation owns the finger until end/cancel; only its one retained coordinator display link may edge-autoscroll the vertical timeline. Restore every normal gesture immediately on exit.
- After release, React creates the DST-safe blank/Uncategorized/tag-free 30-minute draft, presents the existing `ActiveTimerEditSheet` in Add mode, saves through `createManualTimeEntry`, and refreshes bootstrap. Do not change the Plus route, prefill from timer/recent/place metadata, or stop/replace an active timer.

## Review Checklist

- [ ] Component follows existing naming and folder conventions.
- [ ] Props and types are explicit.
- [ ] Error and loading states are handled.
- [ ] Mobile and desktop layouts are checked.
- [ ] No text overflow or overlapping UI.
- [ ] Web fields have one focus owner and shared geometry; compound nested actions remain independently keyboard-visible.
- [ ] The persistent web timer keeps equal control heights, a fixed Play/Stop slot, one fixed Plus/More slot, stable idle/running geometry, truncating Category text, and no horizontal overflow at desktop, compact, phone, or 200%-zoom-equivalent widths.
- [ ] Running start-date/time Save and Enter share one mutation path, never submit the outer timer form, persist after refresh, and keep redundant calendar/clock affordances out of the tab order.
- [ ] Positioned Calendar blocks preserve title-first density, normal-opacity Running text, valid sibling interaction semantics, keyboard/touch action parity, and the documented direct-resize height policy at every zoom.
- [ ] Calendar compact editing preserves pointer/Space/Enter/double-click focus semantics, create autofocus/return focus, empty-space fine-pointer creation, floor-to-slot/default-duration math, consumed-pointer lifetime through Calendar release, dirty/busy scroll-away ownership, semantic block protection, past-only and DST-exact timestamps, create/edit payload fidelity, mutation-scope ownership, same-duration anchor following, failure rollback, canonical-over-provisional layering, and Reduce Motion.
- [ ] Timer mutations feel immediate and do not show non-refresh loading indicators.
- [ ] Dashboard changes preserve the core timer/start-task flow.
- [ ] Permission controls are not placed on the dashboard.
- [ ] Native iOS views preserve the React data/mutation boundary and do not reset interaction state during ordinary prop refreshes.
- [ ] Moving components cover entrance, reflow, exit, interruption, async rollback, and Reduce Motion states that apply.
