# Component Guidelines

Use this when working on frontend components.

The contracts below describe the shipped components. The approved Dayframe Blocks direction (see `docs/brand-style-guide.md`) replaces some of them, for example circular category markers and soft calendar fills. Each surface changes only in the redesign PR that migrates it, and that PR updates the matching contract here.

## Component Structure

- Keep components focused on one responsibility.
- Prefer existing UI primitives and local component patterns.
- Keep data fetching, mutations, and presentation responsibilities clearly separated.
- Use accessible labels, semantic HTML, and keyboard-friendly controls.
- Keep Dayframe timer surfaces category/task-first. Avoid exposing projects/clients in primary timer UI.
- Mobile running Stop is accepted after its account-owned local Stop intent persists, then the existing `ActiveTimerEditSheet` remains the sole exit-animation owner. HTTP delivery never owns dismissal. Idle Today reserves no Stop-status copy row: the idle card shows `NOTHING RECORDING`, `What are you working on?` and its `Start a block` and `Add past time` pills, and the quick-start mosaic follows the card. Retryable Stop delivery remains visible through the shared header sync icon without spinner, progress, modal, blocking alert, or loading-driven reflow; Reduce Motion uses the existing sheet/layout path.
- On web, Dashboard and Timeline must consume the one timer runtime mounted by `AppShell`. Route components must not mount an independent active-timer poll, store, API client, mutation queue, shortcut handler or manual-entry owner; navigation between those routes must preserve the same optimistic state and active-entry identity.
- Keep the persistent web timer on one explicit measured track: a flexible `minmax(0, 1fr)` task compound control, bounded Category and time tracks, a stable Play/Stop slot, and one final icon-action slot where idle Plus becomes running More. Idle/running swaps must preserve outer geometry; compact layouts may reflow the task field to its own row but must not shrink or overlap the remaining actions.
- Manual-entry Suggestions must reuse timer suggestion ranking and metadata without invoking timer start. Selecting one fills the manual draft's Description, Category, and Tags. Cap the visible result set to a documented number of complete content-safe rows; never force a two-line title/metadata row into the generic 44 px touch minimum or crop a partial final row. Its Tags/Suggestions surfaces remain out of flow, anchor to their actual triggers, and must not require scrolling the dialog merely to reveal the options.
- Add time must reuse the timer Category option treatment rather than a separate native select. Date/time controls retain click-to-select behaviour and use a Dayframe-owned calendar/time surface when the opened browser-native picker cannot be themed; styling only the closed native field is not sufficient evidence. Dialog child surfaces must preserve the dialog's rounded silhouette without forcing floating pickers back into a clipping container.
- Timer-owned Suggestions, Tags, Categories, and start-time surfaces must use the shared floating-surface treatment and escape the timer panel's clipping boundary. Keep their lists internally scrollable, their triggers visually connected, and phone-width variants fully inside the viewport; do not substitute a scrimmed modal for an anchored timer editor.
- `CategoryPicker` owns contextual category creation for the idle/running web timer, Add Time, Timeline List entry editing, and Calendar create/edit. Every create-enabled instance portals its panel outside the editor's scrolling content: use the nearest native `dialog` root when one exists and `document.body` otherwise. Match the category field width, prefer a 6px below-trigger gap, flip above when required, clamp to 12px viewport gutters, recalculate for panel/trigger resize plus page/visual-viewport scroll, resize and zoom, and keep only the panel internally scrollable with a 220px maximum. Opening the list or Create state must not change the surrounding editor's bounds, `scrollHeight`, or `scrollTop`; all portalled category surfaces remain inside the editor's outside-pointer, blur, Tab, focus-trap and Escape interaction boundary. Closed fields and list options show the category's circular, borderless, shadowless colour dot. The final option swaps the list for a bounded inline editor without mounting a nested form: place the accessible colour-dot action inside the leading edge of the Category name compound control instead of adding a separate Colour row, preview the same deterministic automatic colour the server will assign, allow an optional choice from all 30 canonical palette colours in the shared five-column order, and keep the colour palette in its own viewport-clamped floating surface so neither editor nor category panel reflows. Create is a standalone workspace catalogue mutation: send the trimmed name plus only an explicitly chosen palette key, keep `isPinned=false`, publish the returned row to shared bootstrap state, then select it in the local draft. Never submit, dismiss, start, stop, restart, save, or reset the surrounding entry; Description, Tags, dates and times remain under their existing owner, while the category survives later draft discard. Block blank and case-insensitive duplicate active names on both client/server boundaries; failure retains name, chosen colour, draft and focus for retry. Enter belongs to category Create; Escape closes Colour, then returns to the option list, then the trigger; arrow/Home/End navigation includes Create and colour-grid navigation; phone widths keep a 12px viewport gutter plus 44px targets. Reports, Review, Places and Automations must not opt into contextual creation.
- `CategoryPicker` also owns its create-state visual anatomy across hosts. Use 14px/650 for the embedded heading and actions, 12px/650 for the Name label, and 14px/400–500 for input and option text. Centre the 20px create swatch in a 44px leading action inside the field's 2px perimeter, producing a 14px visible edge inset and 24px centre offset. Its final list action uses a separate 1px divider inset 12px with 6px clearance before the rounded action surface; it must not use the action's border or inset shadow. Timer and compact-editor rules may style only their direct option rows, never every descendant button or the shared create form.
- The running start-date/time editor is content inside the persistent timer form, never a nested form. Enter and pointer Save must call the same direct update path, prevent outer timer submission, update elapsed state immediately, and persist after bootstrap reconciliation. Calendar/clock affordances may remain pointer-clickable but must use `tabIndex=-1` when the segmented native date/time control already provides the editable keyboard stops.
- Web date selection uses `DayframeCalendar`: a stable six-week grid with muted, selectable adjacent-month dates. Date-time consumers add their own typed time control; date-only consumers must not fork the calendar geometry.
- Reports filter disclosure content is a floating surface, not in-flow expansion. Categories, Tags, Place, Source, and More filters must preserve the report layout below them, use bounded internal scrolling, and keep URL-backed multi-selection semantics.
- Web workspace management uses one compact selector with immediate switching; Rename and New workspace reveal only their relevant form. Profile-menu workspace rows use the same flat, fill-led menu treatment as Settings and Log out, without per-row elevation.
- Category identity uses circular colour markers. Colour-choice controls must keep an accessible target while the visible swatch remains circular, borderless, and shadowless; selected state comes from focus/selection treatment rather than changing the swatch shape. Category Save is text-only and Edit uses a pencil.
- The desktop sidebar may expose one icon-only Light/Dark toggle immediately above Help & Shortcuts. Its accessible name describes the destination theme, and it switches from the resolved System appearance to an explicit opposite choice.
- Route-level Settings should consume the shell's last successful bootstrap snapshot and refresh quietly. A full loading state is only for a tab with no cached authenticated data; background reconciliation must not blank the route, cross user/workspace boundaries, or overwrite an active form.
- Custom checkbox switches must explicitly own track and thumb geometry (`appearance`, fixed/min/max dimensions, border radius, padding, and box sizing) so iPad/WebKit touch styles cannot distort the pill.
- For positioned web Calendar blocks, use one structured primary line in `Description · Category · #FirstTag +N` order at every readable height, including `title` overlap lanes. Description is semibold primary text; Category is muted normal weight; the first tag is muted bold; `+N` is muted medium. Actual rendered widths at or below 111px hide the metadata spans and retain Description only; below 18px or at `none` density show no text. The independent full-entry `Duration (Start – Finish)` secondary line starts only at the safe 48px height. Running state must not reduce whole-block text opacity.
- Live web Calendar blocks use one compact radius across densities and a subtle category-derived hairline border over the soft category fill; do not restore a leading accent rail. Selection is fill-led, while keyboard focus alone owns the explicit focus perimeter.
- Separate touching Calendar blocks with visual-only vertical and horizontal gaps after semantic time/lane calculation. Do not falsify timestamps, durations, snapping, overlap classification or minimum-height collision inputs to create spacing.
- Calendar overlap layout uses shared deterministic intent: isolated entries are full width; a substantially shorter interval contained within one longer interval may use an inset overlay that leaves the longer rail visible; partial, similar, or multi-entry collisions use equal lanes; dense lanes may suppress text. Renderers own only geometry interpolation and hit testing. Every visible block must remain the tap target for its semantic entry.
- A positioned Calendar container must not itself be an interactive wrapper around actions. Give selection/details one primary action, keep restart and pointer-resize as siblings, provide keyboard and touch equivalents for hover actions, and define a minimum rendered height before mounting direct resize handles.
- Inline Calendar Play is pointer-hover-only and must have an equivalent keyboard/touch Start again route in the selected action surface or editor. Completed blocks at least 24px high may mount Play regardless of lane text density; selected, running, resizing, sub-24px, coarse/hoverless, and rendered widths below 28px hide it. Keep Play above the resize strip only within its own right-edge action zone so the remaining resize handle stays usable; never let the two hit targets intercept each other.
- Calendar and List restart actions must reuse the shell-owned timer runtime and its mutation gate. Copy only category, description, and tags unless the timer contract is deliberately expanded in a separate change.
- Web Calendar, Timeline List, and Reports entry editing share one `TimeEntryQuickEditor` controller/panel contract. Calendar renders it in one `document.body` portal anchored to the exact selected rendered fragment by a stable entry/block identity; List and Reports render the same panel in a centred, focus-trapped, mobile-safe modal. All edit entry points, including Calendar pointer, Space, Enter, and double click, must reach this shared editor; do not restore `EditTimeEntryDialog`, an advanced Calendar editor, or an in-flow bottom action card.
- The shared quick editor owns Description with reusable Tags, Category, explicit Start date/time, completed-entry Finish date/time, and completed/new minute-only `HH:MM` Duration. Exact canonical seconds remain internal and survive no-op and non-temporal saves; a deliberate Duration edit resolves to whole minutes. Every Start, Finish and Duration value uses the same 15px/21px regular foreground typography. Running Duration is live, minute-only, and read-only and running Finish reads `Running`; a ticking duration is presentation state, never a dirty draft value. A running entry places the existing subtle `Running timer` status below the header title rather than in the fixed footer. Start/Finish date triggers reuse the portalled `DatePickerPopover`/`DayframeCalendar`, show only a bare calendar icon inside the same seamless compound field while closed, and return focus to that icon when dismissed. The compact temporal row shows a subtle `+N` beside Finish when its local date is later than Start. Plain Enter in focused Description uses the shared Save path only after hashtag suggestion, modifier, and IME precedence. It does not expose Place or task Suggestions.
- Shared quick-editor saves emit only owned partial keys (`description`, `categoryId`, `tagNames`, `startedAt`, `stoppedAt`). Tags hydrate from the entry, use the shared maximum and create/select/remove behavior, and stay in the same draft/discard boundary as the other fields. Save, Start again and Delete establish one synchronous mutation owner before awaiting: the complete editable form—including Description, selected tags and tag panels—is disabled, duplicate/conflicting actions are gated, the dialog exposes busy/status semantics, and failure restores the exact draft plus the initiating focus. Start, Finish and Duration validation inputs describe the mounted editor-scoped error element only while their corresponding error is visible. Hidden Place and compatibility metadata must survive every save and active-timer optimistic update. Calendar and Timeline List may expose Start again and Delete; Reports exposes neither, and List grouping continues to edit its existing representative occurrence.
- Calendar empty-space creation is owned by one primary fine mouse-pointer down/up sequence on the day body. Require the same pointer and day, movement below the drag threshold, unchanged Calendar scroll, an eligible underlying target and no active resize or consumed-dismissal token. Reject touch/coarse input, right-click, drag, scroll, cancellation, headers, axes, scrollbars, blocks/actions/handles, the temporary anchor and each block's full semantic time rectangle, including any visual-only gap.
- Click-to-create floors local wall time to the preceding 15-minute slot and proposes an exact 30-minute interval. Use a discriminated create target rather than a fake `TimeEntryRow`; render one `aria-hidden`, `pointer-events: none` provisional anchor whose geometry follows draft Start/Finish and zoom without entering canonical entries, totals or lane layout. At 23:45, Finish is 00:15 on the next local date.
- Create mode reuses the compact editor's Description/Tags compound control, Category, Start, Finish, Duration, Close, Cancel, Save, validation, overlap, fixed feedback plane and responsive placement. It starts blank, tagless and Uncategorized, uses minute-only `HH:MM` Duration, omits Play/Delete, treats the click baseline as clean but valid to Save, and sends only selected `tagNames`, optional trimmed Description/Category and exact timestamps through the existing manual-entry runtime. Retain the exact draft/anchor on failure; dismiss only after canonical refresh; never mutate the active timer.
- All web focus indicators use the reusable neutral grey `focus`/`control-border` treatment. Text/date/time/select/textarea fields show their neutral focused border for pointer and keyboard focus; buttons, links, tabs, dropdown/icon actions and other non-field controls show a neutral indicator only under `:focus-visible`. Never use browser-blue, `info`, or accent colour to communicate focus. Selected/active states remain independent, and an invalid focused field retains its danger cue alongside neutral focus.
- Compact Calendar controls use that neutral focus treatment. A clean outside click dismisses; Close, Escape or an outside click after any exact draft-value change must switch the fixed feedback plane to exactly `Discard changes?`, `Go back`, and `Discard`, blocking the underlying action. The plane priority is `discard > validation/save error > overlap > empty`; compact overlap content is one icon-free line, `Overlaps one entry by HH:MM` or `Overlaps N entries by HH:MM`, with no warning fill. State changes must not resize or move the editor, and long errors scroll inside the fixed plane. Go back or Escape returns exact focus/draft; Discard uses the editor exit owner. The outside-pointer owner must publish exact pointer identity before dismissal so that pointer cannot also create an empty-space draft.
- Compact Calendar temporal saves have one active owner and synchronize as soon as the active input is complete and valid: Start preserves the exact current duration and moves Finish; Finish recalculates exact Duration; Duration keeps Start and moves Finish. Incomplete time input remains raw with no immediate error until blur/Save. Duration accepts minute counts (`30`, `30m`, `90`, `90m`), `H:MM`/`HH:MM`, written hours/minutes, and compatibility `H:MM:00`; it normalizes to unbounded-hour `HH:MM`, rejects explicit non-zero seconds, and has a one-minute edited minimum. Untouched exact timestamps and hidden seconds remain byte-for-byte canonical, including sub-minute entries displayed as `00:00`. Manual Finish less than or equal to Start remains visible and reports exactly `Finish must be after Start`; only the initial click-created midnight interval may roll to the next day. Ambiguous wall times choose a valid positive interval closest to the exact sources, and nonexistent wall times are invalid. Saves emit only owned partial fields; a future Start remains invalid, while a completed entry may Finish in the future.
- A running compact edit must use the shell-owned timer mutation gate and atomically project the same Description/Category/Start values into bootstrap collections and the persistent timer draft. Preserve hidden tags, place and compatibility metadata; issue one PATCH plus one forced refresh; apply authoritative `updatedAt`; cancel/gate stale debounced timer writes; and roll both snapshots back exactly on failure.
- Calendar portal placement is fixed and measurement-driven: prefer 8px below, flip above, clamp at 12px, and use a full 12px-gutter bounded phone card. Observe the anchor, panel, Calendar scroller, viewport and visual viewport; recompute on scroll, resize and zoom; never animate `top`/`left`; close if the anchor is detached or no longer intersects the Calendar viewport.
- Keep the iOS dashboard focused on logo/header, active timer, start task, the quick-start mosaic, and Today summary.
- Today is a Dayframe Blocks surface. The idle card and the live block follow the prototype's cards (`apps/mobile/src/components/today/todayBlocksLayout.ts`, parity step 2b-1): a 26-point radius and each card's natural height, so Start and Stop change the card's height and the mosaic and Review nudge below move under Reanimated layout transitions. The idle card (20-point padding) shows the `NOTHING RECORDING` eyebrow, `What are you working on?` in Bricolage Grotesque, and two pills: the coral `Start a block` (the screen's single primary action; it starts a bare timer and opens it) and a quiet `Add past time`, kept until the Play orb and entry sheet take it over. The live block (18-point padding, 16 at the bottom) is a solid block in the activity's per-theme display colour with `blockColorsFor` text (never dimmed by opacity): the activity icon and name in a chip and `Recording`, the description, the rolling `H:MM:SS` timer (`LiveOdometer`: 58-point Bricolage Grotesque Bold with tabular figures in fixed 0.62 em digit cells, scaled with Dynamic Type to the numeric cap and shrunk only as far as needed to fit the card, never clipped or wrapped), then the start time beside Add past time (44 points) and the on-block Stop (56 points, shadowed). When the start time is too wide to sit beside the actions, the footer moves the reserved action space to its own line. An entry with no activity uses `surfaceRaised` and says `No activity`. The whole block is one `Edit running timer` button (activity, title and spoken elapsed as its value; the odometer is hidden from VoiceOver); Stop and Add past time stay separate buttons. Only the live block carries the breathing ring. The timer's colon dots stay at 50 % opacity as in the prototype (decorative separators, not text; the digits are full colour).
- Pull the live block left past 90 points to switch (parity step 2b-2; a touch starting on Add past time or Stop does not swipe): a neutral "Switch" underlay shows behind it, and letting go opens the Switch sheet ("SWITCH" / "Pick up something recent"): up to six recently finished blocks with a description, newest first, one per activity and description, leaving out what is recording (`switchRecents` in `apps/mobile/src/lib/todaySwitch.ts`). Each row shows the activity block, the description and "Work · last Tue 6" ("Work · today", "Work · yesterday" when recent) with a Play glyph; the list is taken when the sheet opens; tapping one starts it through the Dashboard's Start owner (the running block stops first) and closes the sheet. With nothing to offer the sheet says "Finished blocks with a description show up here." VoiceOver reaches the sheet through the live block's "Switch" action.
- Stop on the live block flies it into its row (parity step 2b-3): a ghost of the block (`StopFlightOverlay`) shrinks onto the row's activity block, which pops while the row lights up; the idle card arrives at once. Today's pull-to-refresh shows six small activity-coloured blocks that stand up as you pull and pulse while refreshing (`TodayPullBlocks`; the native control's spinner is transparent). Reduce Motion skips the flight and the pulse.
- The Play orb (Blocks parity step 3; `PlayOrb`) is a 64-point coral orb with a soft coral shadow drawn by the Dashboard over the tab bar's trailing slot on every tab: the tabs layout adds a disabled `role="search"` native item (route `orb`, never selected; a deep link redirects to Today) so iOS moves the three tabs left and leaves a circle at the trailing edge. Tap: start a bare block (the entry sheet opens) or, while running, Stop (shown as the stop glyph with a coral seconds ring). Hold 360 ms: the bloom (scrim, "START"/"SWITCH TO" eyebrow, "Slide to a block" in Bricolage, hint) fans out up to nine activities (pinned first, then the last seven days) as 54-point blocks on two arcs; slide to one and release to start or switch to it. VoiceOver uses the native item (its `accessibilityLabel` says "Start a block" / "Stop timer", since a system search item keeps its own title); the coral view is hidden from it. On iPad and before iOS 26 neither the orb nor its slot exists (fixed for the process; the idle card, mosaic, Switch sheet and live block keep every action), and the coral orb is drawn only with a session.
- The quick-start mosaic replaces the Quick Actions chips: up to six pinned activities (usage order) as solid blocks in at most three columns, ranked by whole minutes and sized by completed time over the last seven calendar days (`apps/mobile/src/lib/quickStartMosaic.ts`; the running entry is excluded so tiles never resize while the timer ticks, and sub-minute tracking never reorders them). Tiles are absolutely positioned and keyed by activity, and drop in on the app's first paint only. Tiles below 78 points drop their duration; the header wraps at larger text sizes. Idle the heading is `Start a block` (owner, 7 October 2026); while running it is `Switch to`, other tiles switch, and the running activity's tile is marked `Recording` and opens the running timer rather than starting a duplicate. With nothing pinned the mosaic is hidden.
- Today's blocks (`TodayBlockRows`, Blocks parity step 2a-2a) list today's entries under "Today's blocks · N · swipe a row" in one 22-point surface card with hairline dividers. Each row shows the activity as a solid 34-point-wide block whose height follows the time (18 + 22 per hour, 24–56 points; `rowBlockHeight`), the title (description, else activity, else "No activity"), one line of "08:13–10:00 · [N entries ·] Activity", and the duration (coral while running). Repeats stay grouped behind a count badge; tapping the group opens its entries in place, tapping a single row edits it. Swipe right past 96 points to start it again (coral "Start again" underlay), left to delete it (danger "Delete" underlay, the Dashboard's Undo); a running row only resists. VoiceOver reads each row as one button — title, times read "09:00 to 10:00", activity, and the place and tags the row does not show — with "Start again" (or "Switch to …" while a timer runs) and "Delete" actions. A swipe the system cancels never commits. The visible Play button left the rows with the prototype.
- The Today ribbon (`TodayRibbon`, Blocks parity step 2a-3) sits between the mosaic and the Review nudge: "Today · Drag to scrub" over a 46-point, 24-hour strip on the muted surface with ticks every three hours (stronger at 6/12/18), hour labels 00:00–24:00, today's logged entries as solid blocks, time still waiting in Review hatched in its activity colour (from the cached presentation), and a coral now line with a dot; ticks and labels follow the real day on clock-change days. A horizontal drag scrubs: an inverse tooltip sized to its text shows the block's title and "08:13–10:00 · 1h 47m" ("· needs review" for hatched time) or the time and "Untracked", the block under the finger lifts, and entering each block plays the selection haptic. A tap opens what is under it: a logged block in its editor (the running one in the timer editor), a hatched block at its exact Review item. VoiceOver treats the strip as one adjustable element: swipe up/down steps through the blocks in time order and double-tap opens the current one. It rebuilds on the per-minute clock.
- iPhone Calendar (Blocks parity step 9; native `DayframeCalendarRootView`): under the shared header (Dayframe lockup with the connectivity slot, and the account avatar in place of the gear, as on Today) the native view shows the month in Bricolage Grotesque (30 points; the year is added outside the current year), "5h 20m framed on Friday" (confirmed time; "Nothing framed on Friday") and a zoom pill of two 44-point − / + buttons (disabled at the zoom limits). The week strip has no card: the weekday initial, the date in a 32-point circle (filled in primary text when selected, coral when today) and up to three 5×4-point bars for the day's biggest activities by confirmed time (Review excluded, no-activity time neutral). The timeline sits on the canvas with muted hour labels and a coral now line with a dot and a time pill over the labels. Swiping the strip changes week and the timeline changes day, as before. The "covered" figure left Calendar as it left Today.
- "Earlier this week" (`EarlierThisWeek`, Blocks parity step 2a-2b) follows Today's blocks: the six days before today, newest first, each a 44-point button with the weekday and date, a 12-point mini ribbon of that day's entries across 24 hours (activity colours; no-activity entries neutral), and the day's logged total ("2h05"). Tapping a day plays the selection haptic, selects that day in the shared Calendar state and switches to the Calendar tab. Today lists nothing older; Calendar holds it. VoiceOver reads "Tuesday 6 October, 2 hours 5 minutes" with the hint "Opens this day in Calendar".
- Mobile connectivity status has one root state/announcement owner and one fixed 44-point visual slot immediately after the Dayframe wordmark in the shared primary-tab header. The slot remains reserved when settled so status transitions never move the wordmark, staging badge, Settings action or page content. Confirmed offline uses a neutral `textSecondary` cloud-slash and supersedes the other one-slot states. Confirmed online durable work waiting for connectivity, dependency, or retry is background-only and leaves the slot visually empty; only a live reconnect/recovery delivery attempt shows and rotates neutral circular arrows. A live account-owned pending-count transition from non-zero to zero uses a neutral cloud-check for about two seconds before the slot becomes visually empty. Permanent timer Stop or time-entry Edit/Delete rejection uses a persistent neutral cloud-X button that opens Settings > Sync help whenever offline is not current. Rejected Stops restore server timer truth and appear under Sync help › Needs attention ("Timer stop not accepted") with their own Retry and Discard. The root announces each distinct transition once; the focused tab's icon remains one manually revisitable labelled element without duplicate SVG traversal. Reduce Motion preserves short opacity changes but stops rotation. Never infer completion from reachability/pass outcome or use status to disable an offline-capable action.
- Move location and HealthKit permission controls to onboarding and Settings.

## Mobile Reports Revision 3.2

Blocks parity step 10a (iPhone) replaces the top of this surface; the bullets below still hold where they do not conflict:

- Header: the Dayframe lockup with the account avatar (as on Today and Calendar), then "Reports" (Bricolage 30) with the funnel/count action on the right, then a Week · Month · More switch (`ReportRangeSwitch`, 44-point segments on an inset track with a lighter sliding thumb). Week is the default range. More opens the existing date sheet for Today, Year and custom dates (owner decision D9) and then shows that range's short title; its VoiceOver label is "Choose report dates, {full range}".
- Hero (`ReportHero`): the selected total (Bricolage ExtraBold 52, shrinks to fit) over "framed this week" / "framed in October" / "framed today", with a pill comparing the same stretch of the previous period ("+2h 10m vs last week so far", "Same as yesterday so far"). The previous period is a second, best-effort `/api/reports/summary` read (`previousReportWindow`, five-minute grain), read again on every refresh (a cached one shows meanwhile); a failed read, including a failed re-read, hides the pill; custom ranges have none. The pill counts the same selected activities and compares like with like: this period's live total less the confirmed time since the shared five-minute cutoff (`reportTrackedSeconds` over the phone's entries); when last period was shorter (a shorter month) it is compared whole. After a user change (range, day focus, filter) the hero is announced once to VoiceOver; changing range or filter clears a focused day in the same update.
- Week (`ReportWeekColumns`): seven touching columns, each a full-width target 208 points tall and at least 44 wide from a 375-point screen (about 39 at 320-point Display Zoom; nothing overflows), of stacked activity blocks (selected activities, donut order and colours; a column holds 12 hours unless the busiest day holds more; `reportStackHeights` keeps minimum heights and gaps inside the budget, leaving out that day's smallest blocks when not all fit), weekday initials with today in coral. Tapping a day focuses the hero on it ("9h 51m on Wednesday 7 October", no pill) and dims the other columns to 35 %; tapping it again, or changing range or filter, returns to the range.
- Month (`ReportMonthGrid`): a Monday-first grid of 44-point day cells with the date top-left and the day's blocks stacked from the bottom (24 points for the busiest day or 12 hours), today ringed in coral. Cells are read as "9 October, 2 hours".
- Goal streak (`ReportGoalStreak`): Week only, all activities selected and a daily goal set: "N of M days on goal · Within 15% of your 8h day" with one cell per day up to today (success colour when met).
- The activity-over-time chart now shows only for the More ranges (Today, Year, custom); Week and Month show the columns and grid instead.
- Donut (step 10b, `ReportDonutCard`): a 168-point ring (24-point stroke on the muted track, 2.2-point gaps between activities, selected activities in donut order) beside "Slide your finger around the ring to read each activity." The centre shows the total (Bricolage) over the period ("This week", the month, "Today", the year or the custom range). A finger on the ring highlights the activity under it (30-point stroke, others at 35 %), the centre shows its time and "Work · 31%", its row highlights and each change plays the `tick` haptic; the ring owns the touch until release. VoiceOver reads the ring as one adjustable element: swipe up/down steps through the activities and back to the total. Time without an activity is neutral (the theme's muted text colour) here, in the week columns and the month grid.
- Activity rows (step 10b): a separate card of 44-point rows (14-point colour swatch, name, compact duration "2h 10m", percentage of selected time). Tapping a row highlights it in the ring; tapping it again returns to the total. Rows and ring never filter; the filter sheet is still the only filter.
- Filter sheet (step 10b): "REPORTS" eyebrow over "Filter activities", All · None links (44-point targets), the search field, then the activities grouped like the All activities picker (Your own, then the icon groups, A–Z; No activity and unavailable activities under Other) as rows with the activity's solid block and icon and a round check (coral when kept). The full-width coral button names the result: "Show 3 activities", "Show all activities", "Show none". Each toggle and link plays the `tick` haptic. Apply and the shared dismissal rules are unchanged.

- One compact mobile Reports surface has one range chooser and one funnel/count action. Equal compact Today / Week / Month / Year controls sit directly below the shared date sheet handle, not on a permanent strip or below a duplicate title. Both Reports sheets use `SwipeDismissSheet` as the only transition owner. Done/Apply claims one commit; the handle, backdrop, escape, successful swipe, blur and lifecycle/account invalidation discard. Keep the presentation mounted until coordinated exit completion, reject stale presentation IDs, restore opener focus afterwards, and expose no Cancel, Clear or implicit reset-to-Today behaviour.
- The donut centre shows Total: summed confirmed logged activity clipped to the selected range. Concurrent entries count independently; there is no Time covered card or overlap explanation in mobile Reports. Web/Today goal coverage semantics are unchanged.
- Only selected positive categories appear in the donut and compact zero-gap summary list. Sort exact unrounded duration descending, then stable category key ascending, and give the donut that same array. Angles, totals and percentages use the selected denominator, including spoken values. All/include/none stays reversible through the full category catalogue; None is valid and explains No categories selected. Bare ticks/dashes show filter selection, including mixed All. Uncategorized, duplicate names and unavailable stable IDs remain distinct.
