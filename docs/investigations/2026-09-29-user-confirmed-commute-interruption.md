# User-confirmed commute interruption: implementation evidence

This note records a branch implementation of the explicit user-confirmed Review correction. It is not an automatic stop detector and does not establish staging, physical-device, or production acceptance. The only available attachment described the earlier automatic predicate proposal; the later user request governs this implementation. No private location export or owner coordinates are checked in.

## Sanitised B-shaped fixture and provenance

The synthetic fixture recreates the reported 25 September shape: two Home stays, a 39m52s Home→Home composite, six distinct route observations across two sides, and no intervening stay. Its relative coordinates, IDs and times are invented. The user supplies two stop times strictly inside the composite. The proposed inbound and outbound legs each require at least three retained, distinct-time, distinct-coordinate, accurate route observations, observed movement of at least the existing 150 m displacement threshold, at least the existing 800 m displacement from the genuine Home stay to the near-stop route observation, no implied jump above the engine's 120 m/s plausibility ceiling, and no gap beyond the existing twelve-minute continuity ceiling inside that leg. The server checks the parent’s owner-scoped, same-device, same-algorithm, unexpired `location_segment_evidence` links; a broad Visit, geofence callback, single point, mirrored or same-time callback, implausible jump, poor accuracy, simulated or unknown-simulation point, queue/drift without movement, sparse leg, or missing stay centre cannot supply proof. The returned leg IDs are the retained evidence IDs actually copied. One failed leg rejects the entire mutation.

This is deliberately conservative. A user statement supplies interruption times, not route evidence. The manual endpoint records times only and no location, place, category, Visit or activity. Inbound and outbound children copy only their own route links; the original commute retains all six links. The middle interval owns none. No transport mode or time entry is inferred. A true interruption with expired or sparse retained evidence cannot be corrected by this action.

## Endpoint reader audit before migration

The SQL engine/replay writer derives ordinary commutes from two stay IDs and remains unchanged. The only production reader of commute endpoint geometry is the Location Evidence query: its stay joins are already left joins, and it tolerates a missing endpoint centre while rendering the child's observed route. Workspace export and owner deletion were extended/checked for the new endpoint table and lineage. Test/validation scripts that inner-join stay endpoints describe engine-generated ordinary commutes; the new validator exercises endpoint-backed child reads directly.

The additive local and hosted migrations make each stay FK nullable, add a corresponding manual endpoint FK for each side, constrain each side to exactly one source, and validate workspace/user, parent, boundary kind and time in triggers. Existing stay-to-stay rows satisfy the constraints without rewriting history. Hosted manual endpoints have the same own-user/workspace-member RLS shape as other Location tables. A disposable deletion reproduction showed that the original parent FK's `ON DELETE SET NULL` attempted to update a child whose manual endpoint still required that parent. Both migrations now use `ON DELETE CASCADE` for the parent FK. Transactionally rolled-back deletion probes cover the interrupted parent, either original stay, user, workspace and an ordinary commute while checking children, endpoints and lineage. The owner and endpoint checks remain enforced.
