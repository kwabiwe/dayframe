# User-confirmed commute interruption: implementation evidence

This note records a branch implementation of the explicit user-confirmed Review correction. It is not an automatic stop detector and does not establish staging, physical-device, or production acceptance. The only available attachment described the earlier automatic predicate proposal; the later user request governs this implementation. No private location export or owner coordinates are checked in.

## Sanitised B-shaped fixture and provenance

The synthetic fixture recreates the reported 25 September shape: two Home stays, a 39m52s Home→Home composite, six distinct route observations across two sides, and no intervening stay. Its relative coordinates, IDs and times are invented. The user supplies two stop times strictly inside the composite. The proposed inbound and outbound legs each require at least three retained, distinct-time, distinct-coordinate, accurate route observations, observed movement of at least the existing 150 m displacement threshold, at least the existing 800 m displacement from the genuine Home stay to the near-stop route observation, no implied jump above the engine's 120 m/s plausibility ceiling, and no gap beyond the existing twelve-minute continuity ceiling inside that leg. The server checks the parent’s owner-scoped, same-device, same-algorithm, unexpired `location_segment_evidence` links; a broad Visit, geofence callback, single point, mirrored or same-time callback, implausible jump, poor accuracy, simulated or unknown-simulation point, queue/drift without movement, sparse leg, or missing stay centre cannot supply proof. The returned leg IDs are the retained evidence IDs actually copied. One failed leg rejects the entire mutation.

This is deliberately conservative. A user statement supplies interruption times, not route evidence. The manual endpoint records times only and no location, place, category, Visit or activity. Inbound and outbound children copy only their own route links; the original commute retains all six links. The middle interval owns none. No transport mode or time entry is inferred. A true interruption with expired or sparse retained evidence cannot be corrected by this action.

## Endpoint reader audit before migration

The SQL engine/replay writer derives ordinary commutes from two stay IDs and remains unchanged. The only production reader of commute endpoint geometry is the Location Evidence query: its stay joins are already left joins, and it tolerates a missing endpoint centre while rendering the child's observed route. Review presentation, correction locking and reconciliation identify commutes by segment ID. Automatic semantic emission receives engine-generated stay-backed segments, never manual children. Workspace export and owner deletion were extended/checked for the new endpoint table and lineage. Test/validation scripts that inner-join stay endpoints describe engine-generated ordinary commutes; the new validator exercises endpoint-backed child reads directly.

The additive local and hosted migrations make each stay FK nullable, add a corresponding manual endpoint FK for each side, constrain each side to exactly one source, and validate workspace/user, parent, boundary kind and time in triggers. Existing stay-to-stay rows satisfy the constraints without rewriting history. Hosted manual endpoints have the same own-user/workspace-member RLS shape as other Location tables.

## Replay and Review ownership

A focused failing test first demonstrated that an existing protected manual/superseded composite with the same client segment ID still appeared in replay output. The narrow guard now suppresses only that same-ID manual/superseded commute candidate. It does not change ordinary same-ID accepted/ignored handling. The parent keeps its durable event, accepted Review, full lineage and manual/superseded state. Child IDs are distinct, and each child gets a `commute_detected` event and open Review. The action, source reservation, immutable request, receipt, retry, conflict restoration and terminal presentation proof use the existing Review mutation/outbox owners. Receipt acknowledgement requires two child segment IDs, two child Review IDs and no entry ID. Each child has `manual` continuity and is never eligible for automatic confirmation, including `v2_enabled`.

## Mobile motion contract

The trigger is expanding More options on the existing Location Evidence editor. Its existing Reanimated local layout owner controls entrance, field reflow and exit; the new fields have no competing animation owner. Date and time drafts remain mounted while editing, and the existing outer scroll/keyboard inset owns focused visibility. Pressing Save first commits the immutable Review intent to SQLite, then dismisses; a failed local commit leaves the editor and draft visible. A server rejection restores the parent from the outbox's saved anchor. Rapid repeat is gated by the existing in-flight action lock. Reduce Motion uses the existing immediate local presence/layout path. Physical keyboard, VoiceOver and large-text behavior remain separate acceptance work.

## Validation boundary

The local fixture and disposable PostgreSQL validation prove the SQL/action/replay contract, not the precise route or stop times of the real 25 September capture. The implementation uses no automatic stop inference. Ordered local setup and the hosted SQL each applied twice on fresh disposable PostgreSQL 17 databases; the correction/replay validator passed against both resulting schemas, and hosted RLS had two endpoint policies. The hosted run used stubbed auth functions solely to parse and verify the new RLS SQL; it is not a staging migration. No staging, CI/Vercel polling, iOS build, signed-device, production or TestFlight action is part of this PR.
